# go-btse

Unofficial Go client for BTSE, generated from the OpenAPI and AsyncAPI documents BTSE publishes. For using the client from an agent, read [.agents/skills/go-btse/SKILL.md](.agents/skills/go-btse/SKILL.md). This file covers changing the repository.

## Architecture

The root `btse` package covers spot REST operations. Separate `futures`, `markets`, `wallet`, `earn` and `otc` packages prevent collisions between product schemas and operation IDs. Every generated package has its own `gen.go` and config.

`scripts/fetch-spec.sh` downloads `https://docs.btse.com/specs/{product}-rest.openapi.yaml` into `api/`. oapi-codegen reads each complete document unchanged and writes `client.gen.go` beside the package's config. The WebSocket pipeline downloads `{spot,futures,otc}-websocket.asyncapi.yaml`, converts AsyncAPI 2.6 to 3.0 and invokes gen-asyncapi for `ws/spot`, `ws/futures` and `ws/otc`.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- gen-asyncapi, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the root spot package.
- `futures/`, `markets/`, `wallet/`, `earn/`, `otc/`: REST product packages.
- `auth/`: HMAC-SHA384 signing, shared by the generated clients.
- `ws/`: generated WebSocket clients and schema-based message fixtures.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec downloads, conversion, lint and security scans.
- `internal/cmd/convert-asyncapi/`: the AsyncAPI 2.6 to 3.0 converter.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Downloaded specs are inputs, never release artifacts. Never hand-edit generated output.
- gen-asyncapi requires AsyncAPI 3.0. Preserve the conversion step for the provider's 2.6 WebSocket documents.
- The WebSocket converter repairs misplaced schemas and example-only command payloads, and specializes received messages by channel topic. Spot and futures need the `ws.HeartbeatTransport` adapter for plain text heartbeats.
- Without the `number` to `float64` mapping in `config.yaml`, prices and amounts become `float32`.
- BTSE signs the API path without query parameters. The signer strips the REST service prefix before `/api/`, and must run after other URL or body editors.
- Method names come from each spec's operation IDs. Identical names in different products belong to different packages.
- `make generate` downloads current specs. Review its output when upstream changes.
- Tests use local HTTP servers and WebSocket fixtures. They never call BTSE.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
